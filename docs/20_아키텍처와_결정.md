# 아키텍처와 주요 결정

## 데이터 흐름

```text
[학생/교사 브라우저] ──WS /ws/:code──▶ [Worker] ──▶ [ClassSessionDO(code)]
      ▲                                           │  ClassHost (packages/core/host)
      │ state(view, 역할별 필터) / segment(궤적)   │   ├ 참가자·팀·설정
      └───────────────────────────────────────────┘   ├ 단계 상태기계 (LOBBY→BUILD→INTRO→[PLAN→BATTLE]×6→PITSTOP…→PODIUM)
                                                      ├ 마감 시 runSegment() (packages/core/physics) → 9초 궤적 20Hz keyframe
                                                      └ 봇 계획 planForBot() (packages/core/bots)
[혼자 연습] LocalTransport 가 같은 ClassHost 를 브라우저에서 실행 (setTimeout 으로 마감)
```

- `ClassHost` 는 시간을 인자로 받고(`now`), 예약은 `nextWakeAt()` 로만 알린다. DO 는 `storage.setAlarm`, 로컬은 `setTimeout` 으로 감싼다. 같은 코드가 서버·솔로에서 돈다.
- 뷰(`viewFor(playerId)`)는 역할별로 걸러진다: 내 팀 제안·확정 명령만 보이고 다른 팀은 "확정 여부"만. 확정 명령은 전투 시작 시 `revealedPlans` 로 공개된다.
- 전투 구간은 서버에서 한 번만 계산해 `segment` 메시지로 방송하고, 클라이언트는 `startAt`(서버 시각) 기준으로 보간 재생한다. 시각 차이는 ping/pong 왕복 표본의 중앙값으로 보정한다.
- 재접속: `hello` 에 현재 뷰 + 현재 구간을 함께 보낸다. 구간이 없으면 `getSegment` 로 요청.

## Durable Object

- 클래스 코드 = DO 이름(`idFromName`). SQLite-backed(`new_sqlite_classes`).
- 저장: 의미 있는 시점(메시지 처리 후, 단계 진행 후)에 `state` 전체를 JSON 으로 저장. 프레임 단위 쓰기 없음. 최근 구간 4개만 보관.
- WebSocket: Hibernation API(`acceptWebSocket`, attachment 에 `{playerId, role}`). 상시 ping 없음(클라이언트가 12초 간격 ping, 시계 보정용).
- alarm: `min(다음 단계 마감, 만료 시각)`. 만료(24h 무활동, 연결 없음) 시 `deleteAll`.
- 중복 방지: `tick(now)` 는 마감 도달 시에만 진행하고 진행 후 마감을 새로 세팅하므로 알람 재시도·동시 준비 완료에도 한 번만 진행된다. phaseVersion 이 뷰에 포함된다.
- 권한: 교사는 Worker 가 검증한 쿠키 → `x-teacher` 헤더 → attachment 역할. 모든 `teacher:*` 메시지는 attachment 역할로 재검증. 학생 토큰은 DO 저장소의 `tokens` 맵.
- 제한: 메시지 4KB, 소켓당 10초에 60건, 닉네임 10자·특수문자 금지, 클래스 코드 31자 집합 6자리(추측 방지), 교사 로그인 IP당 1분 8회 + 실패 지연 700ms.

## 물리 (packages/core/src/physics/sim.ts)

- 고정 1/60초, 로봇 = 원형 강체(질량·관성·반지름은 빌드에서 파생), 캡슐 = 가벼운 원, 완충벽/경계 = AABB, 낙하·왕관·컨베이어·저마찰 = 센서/영역.
- 접지 모델: 종방향 구동 한계(`A_MAX_GRIP × grip`), 엔진 최고속도(145px/s, 부스터·충돌은 초과 가능), 횡방향 미끄럼 감쇠(`lateralGrip`), 굴림 저항, 제동 감속. 저마찰 패치는 세 값을 모두 낮춘다.
- 회전: 목표 각도(±90°) PD 제어 + 토크 상한(섀시·주행 장치별).
- 장치: 범퍼 = 가동 슬롯 동안 정면 원뿔 첫 접촉에 충격량 + 45% 반동. 플라우 = 정면 충돌 시 상대 +25%/자신 −30%, 가동 시 돌진. 자석 = 정면 55° 원뿔·320px, 거리 감쇠·힘 상한, 반작용 적용, 자성 물체(로봇·캡슐)만. 브레이크 = 저항·횡그립 상승 + 충돌 시 유효 질량 2.2배. 부스터 = 슬롯 시작 +250px/s. 안정화 = 횡그립·회전 상승, 충돌 각속도 교란 감소. 보강판 = 질량 +14, 받는 충격 −20%.
- 충돌(물리 p2, 2026-10-02): 법선 충격량 J=(1+e)·환산질량·접근속도를 양쪽에 같은 크기·반대 방향으로 적용(운동량 보존). 반발계수 로봇 0.75 / 벽 0.5 / 고무 완충벽 0.78 / 플라우 정면 +0.12. 빗맞으면 접선 마찰 충격량(μ=0.45)과 모서리 토크(차체를 정사각형으로 근사)로 스핀. 속도 변화가 40px/s 이상이면 접지 상실(스키드): 그동안 횡그립·조향이 꺼지고 엔진 20%, 등방 미끄럼 마찰(70px/s²)만 작용해 받은 운동량대로 밀려난다. 보강판·안정화·브레이크는 스키드 시간을 줄인다. 범퍼는 양쪽에 같은 충격량(작용·반작용), 발사한 쪽은 대비 자세라 거의 미끄러지지 않는다. 측정: 같은 질량 옆구리 충돌에서 친 쪽 142→16px/s, 맞은 쪽 0→120px/s, 밀린 거리 43→98px(tests/collision.test.ts).
- 충돌 연출(클라이언트): 충격량 비례 스파크·충격 링·화면 흔들림, 충돌 법선 방향 찌그러짐, 국소 히트스톱(표시 시간만 30~90ms 멈췄다 따라잡음), 스키드 자국·연기. 판정에는 영향 없음.
- 왕관 퍽(물리 p3, 2026-10-02): 왕관 코어는 질량 34·반지름 30의 동적 원판. 로봇과 겹치지 않고 반발계수 0.88로 튕기며 벽·완충벽에 0.82로 반사, 미끄럼 감속 40px/s². 자석이 끌 수 있고(반작용 포함) 범퍼는 충격량의 40%를 전달. 낙하 구역에 빠지면 중앙 재배치. 위치는 턴 사이에 유지되고 궤적 프레임 끝에 (x,y)로 실린다.
- 연쇄 충돌: 0.9초 안에 부딪힌 서로 다른 상대(왕관 포함) 수 n 에 대해 e = min(1.4, 기본 + 0.25·(n−1)). e>1 은 초탄성(에너지 주입)이지만 충격량은 항상 양쪽에 같은 크기·반대 방향이라 운동량은 보존된다. 한 프레임에 충돌을 4회 반복 풀이해 충격이 이웃으로 전달된다. 측정: 2대 정면 되튐 82px/s → 4대 집결 131px/s 이상, 운동량 합 ≈ 0.
- 낙하 기여: 마지막 접촉 상대 + 2.5초 창. 왕관: 구간 종료 시 왕관 중심에서 125px 안(왕관 곁)에 단독.
- 결정성: 정수 시드 mulberry32, 부동소수점은 같은 엔진 버전·같은 입력에서 동일(테스트로 확인). 렌더링 프레임 수와 무관.
- 궤적: 20Hz keyframe(위치 0.1px, 각도 0.001rad 반올림) + 이벤트. 6대 기준 구간 JSON ≈ 25~40KB.

## 클라이언트

- React 19 + Vite. 라우트: `/`, `/join`, `/play`, `/solo`, `/teacher`.
- `GameFlow` 가 단계별 장면을 고른다. 교사는 어느 단계에서나 관제 드로어를 연다.
- 렌더러 `ArenaRenderer`(Canvas 2D): 배경 → 영역 → 낙하 → 패드 → 왕관 → 벽 → 캡슐 → 로봇(공통 그림자·팀 링·번호·문양·방향 표시) → FX. 히트스톱/흔들림은 국소 시각 효과.
- 로봇 합성 `RobotSprite`: 섀시 이미지에 하드포인트(JSON)로 바퀴(우측 원본·좌측 미러)·전면 장치(연결점 = 이미지 하단)·보조 장치를 얹는다. 이미지 전체 tint 없음.
- 에셋: `scripts/build-assets.mjs` 가 41장 원본을 트리밍·리사이즈·WebP 변환하고 manifest(id, kind, url, w, h, pivot, trim)를 생성. 장면별 preload, 배경 2해상도.
