# 스크랩 크라운 (SCRAP CROWN) — 개발 계획

작성일: 2026-09-26. 원본 기획서: `01_고철왕_Claude_Code_개발프롬프트.md`, 이미지 명세: `02_고철왕_이미지_제작프롬프트.md`.

## 1. 타이틀

- 확정: **스크랩 크라운 — 고철 도시 챔피언십** (영문 SCRAP CROWN)
- 근거: 경기의 핵심 목표물이 "왕관 코어(PR-04)"이고, 승리 = 왕관 점유다. "고철왕"의 뜻(고철로 왕이 된다)을 유지하면서 스포츠 리그 느낌을 준다. 로고 없이 UI 타이포로 렌더링한다.
- 후보였던 것: 아이언 스크럼, 러스트 리그, 볼트 아레나.

## 2. 사용자 요구로 바뀐 운영 모델 (원본 기획서와 다른 점)

원본은 "6개 방 × 학생 5명, 방마다 개인전"이었다. 사용자 요구는 **팀 대항전**이다.

- 교사가 클래스를 만든다(최대 학생 30명). 학생은 링크/QR + 닉네임으로 입장한다(로그인 없음).
- 교사가 명단에서 **팀장**을 지정한다. 팀장이 지정되는 순간 그 팀장의 **팀이 자동 생성**되고 팀장은 자동으로 조종석(선장)에 앉는다.
- 나머지 학생은 원하는 팀을 골라 들어간다(교사가 자동 배분도 가능). 팀당 최대 인원은 교사 설정(기본 6).
- **한 팀 = 로봇 1대**. 한 경기장에 2~6팀의 로봇이 동시에 싸운다. 30명 → 6팀 × 5명이 기본 추천.
- 교사는 기본 관전자다. 원하면 어떤 팀의 팀장이 되어 함께 참가할 수 있다(그 팀의 기존 팀장은 부팀장으로 내려간다).
- 팀 안의 협업(게임성 개선 포인트):
  - 부품 드래프트: 팀원 전원이 우선순위 투표 → 팀장이 최종 확정. 마감 시 미확정이면 투표 다수결.
  - 명령 계획: 팀원 각자가 3슬롯 명령안을 제안하고, 팀장이 하나를 채택하거나 슬롯별로 섞어 확정. 팀원 제안은 팀 내부에만 보인다.
  - 팀 이모트: 사전 정의 이모트만(자유 채팅 없음).
- 팀이 6개를 넘으면(예: 8팀) 두 경기장으로 나눠 예선 후 상위 팀이 결승. 첫 버전은 6팀까지 한 경기장, 7팀 이상은 확장 항목으로 문서화.

## 3. 기술 구조 (원본 유지)

- pnpm 워크스페이스 대신 npm workspaces(설치 환경에 pnpm 없음). TypeScript 모노레포.
- `apps/web`: React + Vite + Phaser(경기 렌더). `apps/worker`: Cloudflare Workers + Static Assets, `ClassSessionDO`, `GameRoomDO`(SQLite DO, Hibernation WS, alarm).
- `packages/game-core`(규칙·상태기계·점수), `packages/physics`(Matter.js 헤드리스 + 접지 모델), `packages/protocol`(zod 스키마), `packages/bots`, `packages/content`(부품·경기장·균형 데이터), `packages/assets`(manifest).
- 서버 물리만 승패 결정, 9초 구간 사전 계산 → keyframe 궤적 전송 → 클라이언트 보간 재생.
- 교사 인증: 아이디 `teacher`, 비밀번호는 Workers Secret `TEACHER_PASSWORD`(개발 기본값은 `.dev.vars`), 짧은 HttpOnly 쿠키 세션.
- 확장 대비: 부품·경기장·명령카드·게임모드는 content 데이터로 등록, rulesVersion 고정, 새 모드는 `GameMode` 인터페이스로 추가.

## 4. 구현 순서

1. 모노레포 뼈대, protocol/content/game-core/physics 스켈레톤, Worker에서 Matter.js 실행 검증.
2. 세로 단면: 폐차장 경기장, 로봇 2대, 범퍼, 3슬롯 명령, 서버 물리, 점수, 리플레이(솔로 봇전으로 로컬 검증).
3. DO/WebSocket 실제 멀티플레이, 재접속, 단계 마감.
4. 클래스/교사/팀장/팀 참여/관전/봇/QR 입장.
5. 6대 전투, 3챕터, 드래프트·피트스톱·시상대.
6. 에셋 manifest 통합(자동 trim/최적화 스크립트), 접근성·저사양 옵션.
7. 테스트(규칙·권한·물리·복구 1~2회), GitHub push, Cloudflare 배포, 운영 문서.
