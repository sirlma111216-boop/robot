# 고철왕 — 이미지 제작 목록과 개별 프롬프트

이 문서는 외부 이미지 생성 도구와 후편집 작업자에게 전달한다. 실제 이미지를 이미 만들었다는 의미가 아니다. Claude Code는 여기의 ID를 사용해 asset manifest와 장면을 구현한다. 시점·해상도·pivot·장착 위치는 아래 계약을 따르고, 생성 결과는 사람이 확인하고 정리한다.

## 1. 아트 방향과 사용법

“장난감처럼 읽히지만 싸구려처럼 보이지 않는 고철 스포츠 리그.” 귀여운 단순 얼굴, 묵직한 금속, 청록·호박색 조명, 짙은 남색 그림자. 녹과 긁힘은 작은 크기에서 형태를 흐리지 않을 정도로만. 너무 어두운 포스트아포칼립스, 군사 전쟁물, 사실적인 폐허, 픽셀아트, 유아용 교육 삽화는 피한다.

게임 플레이는 **정확한 탑다운 정사영**이다. 부품 윗면을 보고 로봇의 정면은 화면 위다. 배경 콘셉트와 캐릭터 초상화만 영화적인 원근/3분의 4 구도를 쓸 수 있다. 탑다운 로봇에 아이소메트릭 바퀴나 정면 범퍼를 섞지 않는다.

제작 순서:
1. ART-REF-01 스타일 기준판과 RB-02 표준 섀시를 먼저 제작·승인한다.
2. 이후 모든 요청에 승인 기준 이미지를 레퍼런스로 첨부한다. 같은 텍스트만 반복한다고 화풍이 고정된다고 가정하지 않는다.
3. 아래 공통 프롬프트 + 유형별 접미문 + 개별 프롬프트를 합쳐 한 자산씩 생성한다. 개별 요청에 정확한 ID를 작업명으로 기록하되 이미지 안에는 ID를 그리지 않는다.
4. 부품은 단일 오브젝트로 생성한다. 정확한 스프라이트 시트·마스크·알파는 후편집으로 보정한다. 체크무늬 배경이 그려져 있으면 투명 이미지로 인정하지 않는다.
5. 첫 세로 단면에 필요한 P0 자산을 적용해 실제 화면 크기에서 확인한 뒤 P1을 만든다. P1도 최종 3챕터 출시에는 포함한다.

### 모든 이미지에 붙일 공통 프롬프트

> Original art for “Scrap King: Scrap City Championship”, a polished competitive robot sports game. Cohesive stylized 2D painted game art with clean 3D-inspired volume, bold readable silhouettes, compact industrial forms, restrained brushed metal, enamel paint, warm amber lights and cool teal accents against deep navy. Playful engineering, confident craftsmanship, strong material separation, restrained surface wear, clear hierarchy at small display sizes. Consistent soft key light from upper left. Original designs only. No text, letters, numerals, logos, watermark, UI, labels, screenshots, photographic realism, excessive grunge, tiny greebles, or visual noise.

### 유형별 접미문

- **BG:** `Wide cinematic environment illustration, 16:9, 1920x1080 or larger, clean readable focal composition, layered depth, low-detail negative space for UI as specified. No characters or robots unless explicitly requested. No baked-in interface.`
- **AR:** `Exact orthographic top-down arena base, no perspective or isometric tilt, all ground on one plane, 1920x1080. Low-contrast playable floor, unobstructed central 80 percent, decorative depth confined outside the playable boundary. No baked-in obstacles, holes, rails, pickups, moving machinery or gameplay markings. All gameplay props will be separate sprites.`
- **CHAR:** `One isolated character only, expressive three-quarter portrait, waist-up, 1024x1024 transparent PNG, consistent studio lighting, complete silhouette with generous clear padding, no contact shadow or background.`
- **ROBOT:** `Exact 90-degree overhead orthographic game sprite, front points straight up, centered, no camera tilt, no visible side-facing perspective. Isolated on true transparent background, clean alpha edges, soft form shading but no cast shadow. Neutral metal body with a few clearly separated pale accent panels for later team-color masks. No other components unless specified.`
- **PROP:** `Orthographic top-down isolated arena prop on true transparent background, no perspective, same scale language and upper-left lighting as approved robot sprites, clean silhouette, no cast shadow.`
- **FX:** `One isolated game visual-effect element, centered, transparent RGBA, clean soft alpha falloff, readable at small size, no scene, no UI, no text, not a sprite sheet.`

### 공통 제외 요소

`No imitation of an existing game character or franchise, no watermark, no words, no symbols resembling letters, no fake transparency grid, no extra objects, no cut-off silhouette, no unintended perspective, no baked-in drop shadow on modular parts, no glow that hides the attachment point.`

위 영문 프롬프트는 제작 도구에 직접 입력할 수 있다. 제목·대사·점수·버튼은 이미지 안에 생성하지 않고 게임 UI에서 한국어로 렌더링한다.

## 7. 실제 조립되는 로봇 모듈 13종

### 공통 조립 계약

- 섀시 원본 512×512, 바퀴 단품 256×512, 전면/보조 장치 256×256. 모든 로봇은 화면 위가 정면이다.
- 섀시 pivot (0.5, 0.5), 기본 몸체를 중앙 약 256×320 영역 안에 맞춘다. 정확한 경계는 후편집에서 통일한다.
- 장착 위치는 섀시마다 JSON으로 지정한다. 기본 후보는 앞 (0.5, 0.20), 좌 (0.22, 0.55), 우 (0.78, 0.55), 보조 좌/우 (0.36, 0.60)/(0.64, 0.60). 좌표는 전체 정사각형 기준이며 실제 아트에 맞춰 검수 후 확정한다.
- 바퀴는 우측 모듈 하나를 만들고 좌측은 미러링 가능하도록 완전히 대칭적인 디자인. 회전하는 표면은 추가 텍스처 또는 코드 스크롤로 표현한다.
- 전면 장치는 실제 연결 위치가 이미지 하단에 오도록 하고 로봇 앞쪽으로 기능부가 향한다. pivot은 연결 지점으로 지정한다.
- 바닥 그림자는 독립적인 코드/공통 효과로 만든다. 각 부품에 따로 그림자가 있으면 조립 시 중복되어 지저분해진다.
- 플레이어 색은 외곽 링·번호·문양·선택적 페인트 마스크로 표현한다. 완성 이미지를 통째로 빨강/파랑으로 tint하지 않는다.

## 9. 개별 생성하지 않는 파생 자산

아래는 생성형 모델로 다시 그리지 않는다. 승인된 원본과 코드로 만든다. 디자인 언어가 분산되고 제작비가 늘어나는 것을 막는다.

| 파생 ID | 만드는 방법 |
|---|---|
| ICON-PART-* | 각 RB/DR/MD 원본의 동일 비율 크롭, 128/256px 카드 썸네일 |
| ICON-CMD-FWD/BACK/LEFT/RIGHT | 동일 선 두께의 정확한 벡터 화살표. 명령 강도와 방향을 오독하지 않게 검수 |
| ICON-CMD-BRAKE/FRONT/UTILITY/WAIT | 대응 MD 그림 또는 단순 벡터 픽토그램, 텍스트 한 단어 병행 |
| TEAM-01~06 | 6개 고대비 색 + 서로 다른 문양 + 번호. 색각 이상 모드에서도 식별 가능 |
| ROBOT-PREVIEW-* | 실제 조립 모듈을 게임 렌더러로 합성해 생성. 실제와 다른 완성 로봇 그림 사용 금지 |
| UI-PANEL/BUTTON/CARD | 코드/벡터 9-slice 방식. 일정한 모서리·테두리·여백·상태색 |
| SHADOW-ROBOT | 공통 부드러운 타원/복합 실루엣 그림자, 게임에서 하나만 적용 |
| VFX-SKID/TRAIL | 실제 이동 궤적에서 생성되는 짧은 스키드 선/잔상. 배경에 미리 그리지 않음 |
| THUMB-ARENA-* | 승인 경기장과 실제 배치 데이터로 캡처 |

이 파생 항목은 새 이미지 제작 목록에서 빠뜨린 것이 아니라 의도적으로 코드/후편집하는 항목이다.

## 10. 파일 규격, 최적화와 검수

원본 예: `assets-source/images/RB-02.png`, 배포 예: `public/assets/images/robots/rb-02.webp`. manifest의 stable ID는 `RB-02`로 유지한다. 공백·한글 파일명 대신 영문 소문자 파일명을 사용하되 작업 문서는 한국어로 유지한다.

- 배경: 고품질 원본 PNG 보관, 웹 배포 WebP/AVIF 지원을 테스트해 선택. 모바일/저사양용 1280px 파생본.
- 투명 모듈: PNG 원본과 알파 보존 WebP 배포본. 압축으로 외곽에 검정/흰 halo가 생기지 않는지 확인.
- 최종 atlas는 도구로 정렬하고 패딩·extrude를 넣는다. 2048×2048 atlas 여러 장을 기본으로 테스트한다. 4K 단일 atlas를 모든 기기에 강요하지 않는다.
- UI 한국어 글꼴은 배포 가능한 라이선스를 가진 가독성 좋은 폰트를 사용한다. 생성 이미지의 가짜 글자를 그대로 두지 않는다.
- 움직임을 위해 필요한 레이어 분리, 알파 정리, 정확한 마스크 제작은 후편집 작업이다. 생성 도구가 자동으로 완벽히 수행했다고 가정하지 않는다.
- 그림만으로 장착 위치·애니메이션 기준점·콜라이더를 추정하지 않는다. 각 자산의 pivot과 hardpoint를 미리보기 도구에서 맞춘다.
- 1366×768 화면에서 실제 로봇 표시 크기 70~120px로 검수. 6대가 가까이 있어도 앞방향·장착 장치·팀이 구분되어야 한다.
- 이미지가 잘 나와도 게임 바닥이 너무 복잡하거나 전투 피드백을 가리면 다시 조정한다. 실루엣과 동작 가독성이 장식보다 우선이다.

### 수량과 제작 우선순위

총 **41개 개별 이미지 프롬프트**: 제작용 기준판 1 + 배경 8 + 경기장 3 + 오브젝트 7 + 인물/드론 3 + 로봇 모듈 13 + 효과 6. 기준판을 제외한 실제 런타임 원본은 **40개**다. 파생 썸네일·아이콘·팀 마스크·atlas는 별도다.

P0부터 제작해 도시 입구→격납고→부품 선택→정비→폐차장 전투까지 실제 화면을 완성한 뒤, P1으로 다른 두 챕터와 확장 부품을 채운다. 최종 릴리스에서는 필요한 P1이 비어 있지 않아야 한다. 누락 자산은 asset-audit에 ID 단위로 표시한다.
